# 导入：三种查找策略

讲座课我们学了查找策略谱——面对不同数据特征，选择不同方法：

| 策略 | 前提条件 | 核心思想 | 查找代价 | 构建代价 |
|:---|:---|:---|:---|:---|
| **线性查找** | 无序即可 | 逐个比较 | O(n) | 无 |
| **二分查找** | 必须有序 | 范围折半 | O(log n) | O(n log n) 排序 |
| **哈希查找** | 键值映射 | 键 → 索引，直接访问 | O(1) 平均 | O(n) 建字典 |

上周已测线性与二分。今天补上**哈希**，同一组 `temps`、同一个目标，把三列填完。

# 大 O 速查（验证实验用）

| 复杂度 | 含义 | n = 30 | n = 1,000,000 |
|:---|:---|:---|:---|
| O(1) | 与规模无关 | 1 次 | 1 次 |
| O(log n) | 规模翻倍，步数 +1 | ≈ 5 次 | ≈ 20 次 |
| O(n) | 与规模成正比 | 30 次 | 1,000,000 次 |
| O(n log n) | 排序代价 | ≈ 150 次量级 | ≈ 2×10⁷ 次量级 |

**关键认识**：大 O 描述增长趋势。今天用**计数器**测实际比较次数，与理论对照。

# 字典 dict 速查（任务 1 会用）

## 创建与访问

| 写法 | 含义 | 示例 |
|:---|:---|:---|
| `{}` / `dict()` | 创建空字典 | `temp_dict = {}` |
| `{k: v, …}` | 字面量创建 | `{"S-042": 28.1}` |
| `d[key]` | 按键访问（键不存在 → `KeyError`） | `temp_dict[29.5]` |
| `d.get(key, default)` | 安全访问，无键则返回默认值 | `d.get(30.0, -1)` |
| `key in d` | 判断键是否存在 | `29.5 in temp_dict` |

## 增删改与遍历

| 写法 | 含义 | 复杂度 |
|:---|:---|:---|
| `d[key] = value` | 新增或修改键值对 | O(1) 均摊 |
| `del d[key]` | 删除指定键 | O(1) 均摊 |
| `len(d)` | 键值对个数 | O(1) |
| `for k in d:` | 遍历所有键 | O(n) |
| `for k, v in d.items():` | 遍历键和值 | O(n) |
| `d.keys()` / `d.values()` | 键 / 值的视图 | 遍历用 |

## 与列表配合（建哈希表）

```python
temp_dict = {}
for i, t in enumerate(temps):   # i=索引, t=温度
    temp_dict[t] = i            # 键=温度, 值=索引
```

**键的要求**：必须**不可变**（`str`、`int`、`float`、`tuple` ✅；`list` ❌）。

**词频统计常用**：`count[w] = count.get(w, 0) + 1`

# 任务1：哈希查找（约 15 分钟）

**问题**：用**字典**将温度映射到索引，实现 O(1) 直接访问。

**步骤**：
1. 构建字典：`temp_dict[temperature] = index`
2. 直接访问：`temp_dict[29.5]`

**代码框架**：

```python
# 构建哈希表（字典）—— O(n)
temp_dict = {}
for i, t in enumerate(temps):
    temp_dict[t] = i

# O(1) 直接访问
idx = temp_dict[29.5]
print(f"哈希查找：索引={idx}, 比较次数=1（直接定位）")
```

**讨论**：字典的**键**是什么？**值**是什么？

# 任务1 参考答案

```python
temp_dict = {}
for i, t in enumerate(temps):
    temp_dict[t] = i

idx = temp_dict[29.5]   # 5
print(f"哈希查找：索引={idx}")
```

**关键对比**：
- 返回的是**原列表**中的索引 5（构建时 `enumerate(temps)` 记录的是原始位置）
- 二分查找返回的是**排序后**的索引 22——同一个温度，索引含义不同！

**思考**：若列表中有两个 `29.5`，字典会怎样？（后面的覆盖前面的）

# 三种策略对比表（收束填写）

| 策略 | 前提条件 | 本次比较次数 | 构建代价 | 适用场景 |
|:---|:---|:---|:---|:---|
| 线性查找 | 无序列表 | **6** | 无 | 无序、只查一次 |
| 二分查找 | 有序列表 | **2**（最坏 ≈5） | O(n log n) 排序 | 有序、频繁查找 |
| 哈希查找 | 键值映射 | **1**（直接定位） | O(n) 建字典 | 频繁查找、按键访问 |

**一句话总结**：面对我的数据，我会选择哪种策略？为什么？

# 规模化思维实验

将 n 放大到 **100 万**条数据，查找 1 次：

| 策略 | 大约比较次数 | 直观对比 |
|:---|:---|:---|
| 线性查找 | **1,000,000** | 逐个比完 |
| 二分查找 | **≈ 20** | log₂(10⁶) ≈ 20 |
| 哈希查找 | **1**（定位）+ 建表 O(n) | 先花 O(n) 建表，之后每次 O(1) |

**讨论**：100 万次比较 vs 20 次比较，差距是几个数量级？

---
# 盈亏平衡：查多少次才用哈希？

设数据规模 n，查询 k 次：

| 策略 | 总代价（量级） |
|:---|:---|
| 线性 | k · n |
| 哈希 | n + k |

当 k · n > n + k，即 **k > 1** 时，哈希的总代价可能更低（需考虑常数因子）。

**工程直觉**：
- 查 **1 次**、数据无序 → 线性
- 数据**已有序**、查很多次 → 二分
- 需要**按键反复查**、可预处理 → 字典

# 研讨课一收束：典型错误

| 典型错误 | 现象 | 原因 |
|:---|:---|:---|
| 计数器放在 `if` 之后 | 第一个就命中时 count=0 | 应在每次比较**前**加 1 |
| 二分查找找不到 | 用了未排序的 `temps` | 必须先 `sorted(temps)` |
| 混淆两种索引 | 线性得 5，二分得 22，以为错了 | 排序改变了元素位置 |
| `temp_dict[29.5]` KeyError | 构建时键值写反 | 应是 `dict[温度] = 索引` |
| 说"哈希永远最快" | 忽略 O(n) 建表代价 | 只查一次时未必划算 |
| 重复温度覆盖 | 以为字典存了所有位置 | 键唯一，后者覆盖前者 |

# 词频正确骨架

```python
count = {}
for word in words:
    count[word] = count.get(word, 0) + 1
```

审查清单：

| 检查 | 通过标准 |
|:---|:---|
| 首次出现 | 不会 `KeyError` |
| 重复键 | 覆盖是故意的，还是该存列表 |
| 键类型 | `int` / `str` / `tuple`，不是 `list` |
| 查重 | `len(lst) != len(set(lst))` 或 `in seen` |

# 词频数据从哪来？（约 12 分钟）

讲座用的是字符串。把 `demo/fox.txt` 放到 `w5_lab/`，换成**文件**：

```python
count = {}
f = open('fox.txt')
for line in f:                    # 文件按行遍历
    for word in line.split():
        count[word] = count.get(word, 0) + 1
f.close()
print(count)
```

| 检查 | 通过标准 |
|:---|:---|
| 当前目录 | 找得到 `fox.txt`（找不到 → 还 W1 路径的账） |
| 两层循环 | 先按行，再 `split`；不是 `f.split()` |
| 关闭 | 循环结束后 `close()` |

本周**不写** `with`、不写 `encoding`（文件是英文）。有一种写法能保证关上——**W15 揭晓**。

找不到文件会抛 `FileNotFoundError`（讲座 Quick check IV-2）：**不要** `except: pass`，改当前目录。缺键仍用 `get`，不靠裸 `except`。

预期：`the` 与 `fox` 各 2 次，其余 1 次。
