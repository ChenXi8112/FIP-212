# 代码阅读：merge 手推

不运行，在纸上写每步 `result` / `i` / `j`：

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

阅读 `merge([1, 3], [2, 4])`：循环结束后 `result` 是什么？剩余段 `extend` 漏了会怎样？

# 导入：归并排序 vs 快速排序

讲座课已讲归并、切片拷贝、逆序对（作业 C02）。**今天聚焦快排分区**，与归并对照“先排后合 vs 先分后排”。

| 步骤 | 归并排序 | 特点 |
|:---|:---|:---|
| 分解 | 对半切 | 简单 |
| 排序 | 递归排好两半 | Always Believe |
| **合并** | 双指针 merge | **排序发生在合并** |

快速排序——**反过来**：

| 步骤 | 快速排序 | 特点 |
|:---|:---|:---|
| **分区** | 选基准，分 `< pivot` 与 `≥ pivot` | **排序发生在分区** |
| 分解 | 递归排 left 和 right | 基准已在最终位置 |
| 合并 | 拼接 `left + [pivot] + right` | 无需 merge 比较 |

**关键差异**：归并“先排后合”；快排“先分后排”——分区后基准**已在正确位置**。

# 合并 vs 分区（讲座课对照）

**归并**：两个**已排序**子列表 → merge → 有序

[MergeTwoSorted.py](../../2%20课件/7%20分治算法/demo/MergeTwoSorted.py) — 左 4 个 + 右 5 个 → 9 个有序

**快排**：选一个基准 → 左边都更小、右边都更大 → 基准就位

课件示例 `[3, 1, 4, 1, 5, 9, 2, 6]`，基准 `3`：

| left（< 3） | pivot | right（≥ 3） |
|:---|:---|:---|
| `[1, 1, 2]` | `3` | `[4, 5, 9, 6]` |

再递归排序 left 和 right，最后拼接。

# 列表操作速查（快排会用）

| 写法 | 含义 | 快排中的用途 |
|:---|:---|:---|
| `arr[0]` | 第一个元素 | 选取基准（简洁版） |
| `arr[1:]` | 去掉首元素的切片 | 分区时**排除基准本身** |
| `[x for x in arr if 条件]` | 列表推导式（还 W5 开链表；本周加 `if` 过滤） | 构建 left / right |
| `left + [pivot] + right` | 列表拼接 | 合并三路结果 |
| `len(arr) <= 1` | Base Case | 0 或 1 个元素已有序 |
| `random.choice(arr)` | 随机选元素 | 随机化基准，避免退化 |

**易错**：分区必须用 `arr[1:]`，若用 `arr`，基准会重复出现在 left 或 right → **无限递归**！

# 任务 1：简洁版快速排序（必做，约 20 分钟）

**问题**：选**第一个元素**为基准，分为“小于基准”和“大于等于基准”，递归排序后拼接。

**代码框架**：

```python
def quick_sort(arr):
    if len(arr) <= 1:                    # Base Case
        return arr
    pivot = arr[0]
    left = [x for x in arr[1:] if x < pivot]
    right = [x for x in arr[1:] if x >= pivot]
    return quick_sort(left) + [pivot] + quick_sort(right)

print(quick_sort([3, 1, 4, 1, 5, 9, 2, 6]))
# 预期: [1, 1, 2, 3, 4, 5, 6, 9]
```

**IPO**：Input 列表 → Process 分区 + 递归 → Output 有序列表

# 任务 2：已排序列表退化（必做，约 10 分钟）

**测试**：

```python
arr = [1, 2, 3, 4, 5, 6, 7, 8]
print(quick_sort(arr))
```

**观察递归深度**（在函数开头加 `print(len(arr))`）：

- 基准总是**最小值** → `left` 恒为空，`right` 长度每次只减 1
- 递归深度 = **$n$ 层**（不是 $\log n$）
- 时间复杂度退化为 **$O(n^2)$**

**解决方案：随机化基准**

```python
import random

def quick_sort_random(arr):
    if len(arr) <= 1:
        return arr
    pivot = random.choice(arr)
    left = [x for x in arr if x < pivot]
    equal = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort_random(left) + equal + quick_sort_random(right)
```

**思考**：为什么随机化能避免最坏情况？（期望递归深度 $O(\log n)$）

# 变式：三路分区（弹性挑战）

列表含大量重复元素时，简洁版把 `== pivot` 全放 right，递归仍很长。

```python
def quick_sort_3way(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[0]
    less = [x for x in arr if x < pivot]
    equal = [x for x in arr if x == pivot]
    greater = [x for x in arr if x > pivot]
    return quick_sort_3way(less) + equal + quick_sort_3way(greater)
```

**思考**：`equal` 部分还需要再递归排序吗？（不需要，已全相等）

测试：`[3, 1, 4, 1, 5, 9, 2, 6, 1, 1, 1]`

# 归并排序 vs 快速排序（收束对比）

| 维度 | 归并排序 | 快速排序 |
|:---|:---|:---|
| 分治形态 | 分解简单，**合并**复杂 | **分区**复杂，合并简单（拼接） |
| 何时“局部有序” | merge 完成后 | 分区后基准就位 |
| 时间复杂度 | 稳定 $O(n \log n)$ | 平均 $O(n \log n)$，最坏 $O(n^2)$ |
| 空间复杂度 | $O(n)$ 额外空间 | 简洁版 $O(n)$ 新列表 |
| 稳定性 | **稳定** | 简洁版**不稳定** |
| 工程常用 | 外部排序、链表 | 数组原地快排（进阶） |

# 研讨课二收束：典型错误

| 典型错误 | 现象 | 原因 |
|:---|:---|:---|
| 基准选首元素 + 已排序输入 | 极慢，深度 $n$ | 退化为 $O(n^2)$；应随机化 |
| 分区用 `arr` 而非 `arr[1:]` | 栈溢出 / 无限递归 | 基准重复进入子列表 |
| 混淆 merge 与 partition | 以为快排也要双指针 merge | 快排靠分区定位，不靠 merge 比较 |
| 三路分区仍递归 `equal` | 冗余计算 | equal 已有序，直接拼接 |
| `right` 用 `>` 却漏掉相等元素 | 元素丢失 | 简洁版：`>= pivot` 放 right |

# 本周研讨课总结

- **merge**：双指针 + **必须**收尾剩余段
- **快排**：先分区（pivot 排除），再递归；已排序数据选首元会退化成 O(n²)
- **对照**：归并“排序在合并”，快排“排序在分解”
