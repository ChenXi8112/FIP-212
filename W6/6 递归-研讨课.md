# 导入：从斐波那契到整行杨辉三角

讲座课斐波那契：一次调两个更小的 `fib` → 树状重复。

杨辉三角也可以「一次要一整行」：

```
        1          ← pascal(0) → [1]
      1   1        ← pascal(1) → [1, 1]
    1   2   1      ← pascal(2) → [1, 2, 1]
  1   3   3   1    ← pascal(3) → [1, 3, 3, 1]
1   4   6   4   1  ← pascal(4) → [1, 4, 6, 4, 1]
```

**今天的问题**：`pascal(n)` 返回第 $n$ 行**整个列表**（从 0 计）。例：`pascal(4) → [1, 4, 6, 4, 1]`

格子 `pascal(n, k)` 下周讲座再讲。

# 代码阅读：递归展开（15 分钟）

**任务——`fib(4)` 调用计数**（对照讲座课调用树，先不运行）：

```python
def fib(n):
    if n == 0 or n == 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

1. 含 `fib(4)` 本身，共几次函数调用？
2. `fib(2)` 被调用了几次？→ 引出今天“上一行不要算两遍”。

# 递推关系（整行）

| 条件 | 值 | 角色 |
|:---|:---|:---|
| $n = 0$ | `[1]` | **Base Case** |
| $n \ge 1$ | 两端补 `1`，中间 = 上一行相邻两项之和 | **Progress**：先得到 `pascal(n-1)` |

$$
\text{pascal}(n)=\begin{cases}
[1] & n=0\\
[1] + [\,a_i+a_{i+1}\,] + [1] & a=\text{pascal}(n-1)
\end{cases}
$$

第 $n$ 行有 $n+1$ 个数。**上一行只应计算一次**，存进变量再拼。

# 递归速查：整行

## 好写法：上一行只调一次

```python
def pascal(n):
    if n == 0:
        return [1]
    prev = pascal(n - 1)          # 只算一次
    row = [1]
    for i in range(len(prev) - 1):
        row.append(prev[i] + prev[i + 1])
    row.append(1)
    return row
```

## 坏写法：每加一对再调一遍上一行

```python
def pascal_bad(n):
    if n == 0:
        return [1]
    row = [1]
    for i in range(n - 1):
        row.append(pascal_bad(n - 1)[i] + pascal_bad(n - 1)[i + 1])
    row.append(1)
    return row
```

线性递归被拆成**树状**——和 `fib` 同一类爆炸。

# 任务 1：递归实现（必做，约 15 分钟）

**问题**：编写 `pascal(n)`，返回第 $n$ 行整个列表。

**IPO**：
- Input：非负整数 `n`
- Process：`n==0` 返回 `[1]`；否则用上一行拼本行
- Output：长度为 `n+1` 的列表，两端为 1

**代码框架**：

```python
def pascal(n):
    if n == 0:
        return [1]
    prev = pascal(n - 1)
    row = [1]
    for i in range(len(prev) - 1):
        row.append(prev[i] + prev[i + 1])
    row.append(1)
    return row

print(pascal(4))   # 预期: [1, 4, 6, 4, 1]
```

**手工推演（纸上）**：写出 `pascal(0)` … `pascal(3)` 每一行；再标出坏写法里 `pascal(2)` 会被调用几次。

# 任务 1：`pascal(3)` 调用（参考）

好写法（线性）：

```
pascal(3)
└── pascal(2)
    └── pascal(1)
        └── pascal(0) → [1]
```

坏写法（循环里两次 `pascal(n-1)`，`n=3` 时 `range(2)` 共 4 次调 `pascal(2)`）：

```
pascal(3)
├── pascal(2) × 4     ← 拼中间两项，每项读两次上一行
│   └── 每个 pascal(2) 里再炸 pascal(1) …
```

**思考**：`pascal_bad(15)` 会怎样？`pascal(15)` 呢？

# 任务 2：先存再拼（必做，约 10 分钟）

把坏写法改成好写法；可选再加字典 / `@lru_cache`（键是 `n`，返回值是 list 没关系）。

```python
def pascal(n):
    if n == 0:
        return [1]
    prev = pascal(n - 1)
    return [1] + [prev[i] + prev[i + 1] for i in range(len(prev) - 1)] + [1]

import time
t0 = time.time()
pascal_bad(16)           # 坏写法：可能明显变慢
t1 = time.time()
pascal(16)               # 好写法：瞬间
t2 = time.time()
print(f"坏: {t1-t0:.3f}s, 好: {t2-t1:.6f}s")
print(pascal(4))
```

**思考**：好写法的时间大约是多少？（每层拼 $O(n)$，共 $n$ 层 → $O(n^2)$）

推导式本周**能认**即可（还 W5）；也可用 `for`。

# 任务 3：迭代实现（弹性，时间够时挑战）

递归是从第 $n$ 行问到第 0 行；迭代从第 0 行走到第 $n$ 行——同一递推。

```python
def pascal_iter(n):
    row = [1]
    for _ in range(n):
        new_row = [1]
        for j in range(len(row) - 1):
            new_row.append(row[j] + row[j + 1])
        new_row.append(1)
        row = new_row
    return row

print(pascal_iter(4))    # [1, 4, 6, 4, 1]
print(pascal_iter(30))   # 31 个数，瞬间
```

**思考**：迭代版通常比递归好写法还快一点？为什么？（无调用栈；逻辑几乎一样）

# 三种实现对比（收束填写）

| 实现 | 代码简洁度 | `pascal(16)` | 空间 | 工程建议 |
|:---|:---|:---|:---|:---|
| **坏：循环内再调上一行** | 看起来短 | 极慢 / 卡死 | 爆炸调用 | 禁止 |
| **好：上一行存变量** | ★★★ | 快 | $O(n)$ 栈 + 当前行 | 递归思考 |
| **迭代** | ★★ | 最快 | $O(n)$ 一行 | **迭代实现** |

**一句话**：上一行只算一次；递归帮助**理解「行从哪来」**；工程上往往**迭代实现**。

# 研讨课一收束：典型错误

| 典型错误 | 现象 | 原因 |
|:---|:---|:---|
| 循环里写 `pascal(n-1)[i]` | `n=16` 卡住 | 上一行被算了 $2(n-1)$ 次 |
| 忘记行末 `append(1)` | 每行少一个 1 | 两端都是 Base Case |
| `pascal(0)` 返回 `[]` 或 `1` | 类型/长度不对 | 必须是列表 `[1]` |
| 用 `prev[i+1]` 却循环到 `len(prev)` | `IndexError` | `i` 只到 `len(prev)-2` |
| 记忆化键用 list | `TypeError` | 键是 `n`（int）；不要把整行当键 |

**助教禁忌**：❌ 不要直接给完整答案；✅ 可展示匿名错误代码让全班诊断。
