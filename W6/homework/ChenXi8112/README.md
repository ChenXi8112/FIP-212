## 4. 一个错误示范
```python
def pascal_iter(n):   
    row = [1]  
    for i in range(n+1):
        row = [1] + [row[j]+row[j+1] for j in range(i-1)] + [1]  
    return row
```
- **测试**：`print(pascal_iter(0))`（输出 `[1, 1]`）；
- **解释**：这段代码看似没有问题，也的确在`n>=1`时输出正常，但是当`n==0`时却会输出 `[1, 1]`。这是因为当 `n==0` 时，for 循环仍然会执行一次（`i=0`），虽然列表生成式里 `range(-1)` 使得列表生成式最终为空，但是 `[1] + [] + [1]` 最终为 `[1, 1]` ，输出错误；
- **修复**：直接让 `n==0` 时 for 循环不执行即可，可以按下面的方式修改：
```python
def pascal_iter(n):  
    row = [1]  
    for i in range(1, n+1):  # n==0时for循环不执行
        row = [1] + [row[j]+row[j+1] for j in range(i-1)] + [1]  
    return row
```
- **测试**：`print(pascal_iter(0))`（输出 `[1]`）。

## 5. 坏写法与好写法的速度对比

### 5.1 实测数据

- 环境：Windows 11 25H2 / i5-13500H / Python 3.14.6。
- 测试结果：

| 函数            | 输入 `n` | 平均耗时 (µs) | 标准差 (µs) |     调用次数（理论推导） | 测量方式          |
| :------------ | :----: | --------: | -------: | -------------: | :------------ |
| `pascal`      |   8    |   $2.459$ |  $0.016$ |            $9$ | 7 轮 × 20000 次 |
| `pascal_iter` |   8    |   $2.270$ |  $0.041$ |            $1$ | 7 轮 × 20000 次 |
| `pascal_bad`  |   8    | $200,557$ |  $1,942$ |    $1,063,623$ | 7 次单跑         |
| `pascal`      |   16   |   $7.389$ |  $0.151$ |           $17$ | 7 轮 × 5000 次  |
| `pascal_iter` |   16   |   $6.936$ |  $0.141$ |            $1$ | 7 轮 × 5000 次  |
| `pascal_bad`  |   16   |       已中止 |        — | $7.06*10^{16}$ | 手动中止          |

**备注**：`pascal.py` 里是单次调用计时，包含解释器冷启动；表中是多次重复测量的平均值，所以数值更小，两者不要直接比较。
### 5.2 解释
在计算第 n+1 行时，`pascal` 函数只会计算一次第 n 行，但 `pascal_bad` 函数足足会计算 2n 次第 n 行。所以 `pascal` 函数的算法复杂度为 $O(n^2)$（共调用 n+1 次；第 k 层有一个 k-1 次的循环），而 `pascal_bad` 函数则为  $O(2^n*n!)$（每层直接调用上一行 2(n-1) 次）。因此，`pascal` 函数的耗时远远低于 `pascal_bad` 函数。
