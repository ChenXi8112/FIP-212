## 2. 手工推演与错误分析
*   **手工推演**：
    *   `pascal(0)` -> `[1]`
    *   `pascal(1)` -> `[1, 1]`
    *   `pascal(2)` -> `[1, 2, 1]`
    *   `pascal(3)` -> `[1, 3, 3, 1]`
*   **错误示范分析**：
    计算 `pascal_bad(3)` 时，代码会分别计算 `pascal_bad(2)` 和 `pascal_bad(1)`。在计算 `pascal_bad(2)` 内部，又需要计算 `pascal_bad(1)` 和 `pascal_bad(0)`。
    **出现次数**：`pascal_bad(2)` 总共出现了 **2次**。
    **原因**：代码使用了无缓存的朴素递归，每次计算当前行时，都需要重新从头计算上一行，导致产生大量重复的树状递归调用，时间复杂度呈指数级增长（O(2^n)）。

## 4. 错误现象、原因、修改方法及测试
*   **错误现象**：当输入较大的 `n`（例如 `n=30`）时，`pascal_bad` 程序运行极慢甚至卡死，最终抛出 `RecursionError`（最大递归深度超出）或系统内存溢出。
*   **原因**：正如第2题所述，无缓存的递归导致极其庞大的重复计算，指数级的时间复杂度让程序无法在合理时间内完成。
*   **修改方法**：使用字典或数组将已经计算过的行进行缓存（记忆化搜索），或者直接使用 `pascal_iter` 的迭代法（空间换时间）。
*   **验证修复**：将输入改为 30，运行修复后的迭代版 `pascal_iter(30)`，程序瞬间输出结果，测试通过。
