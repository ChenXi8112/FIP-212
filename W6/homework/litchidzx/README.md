## 手工推演
**根据pascal(n)[i] = pascal(n-1)[i-1] + pascal(n-1)[i]**
- pascal(0) = [1]
- pascal(1) = [1, 1]
- pascal(2) = [1, 2, 1]
- pascal(3) = [1, 3, 3, 1]

### pascal_bad(2)出现次数
- pascal_bad(3)[1] = pascal_bad(2)[0] + pascal_bad(2)[1]
- pascal_bad(3)[2] = pascal_bad(2)[1] + pascal_bad(2)[2]
  
**故知共出现两次**

原因：在计算pascal(3)的过程中，我们并没有储存pascal(2)的结果，因此每次计算pascal(3)中的值的时候都需要重新算一遍

**5. 好坏方法以及迭代法的速度对比**

耗时统计与估计：
```powershell
pascal(1000): 0.007
pascal_bad(9) : 2.740
iterate1(1000) : 0.014
iterate2(1000) : 0.002
```
- 由运行时间可以看到坏方法明显比好方法慢，并且随着n的增加，坏方法运行速度以指数倍增加，而好方法所用时间增加速度较慢
- 虽然递归和迭代1的方法的复杂度都是O(n^2)，但是递归法由于会多n次调用，栈帧，参数传递，这些会多出O(n)的复杂度，使得在n比较小的时候，能看出迭代方法的优势（n大了以后其实差不多）
- **在写迭代的时候突然想到，在一个pascal(n)中，每一个值和下一个值其实是有固定的数学关系，所以可以利用这个关系来优化迭代方法**
```ptython
lst.append(int(lst[i] * (n - i) / (i + 1)))
```
利用这一点，我们进一步缩小了我们的复杂度，使得整体复杂度简化为O(n)。并且，在pascal(n)中，pascal(n)[k] = pascal(n)[n-k]的，因此我们其实只用算一般就可以获得所有的值

**这其实提示我们一点：想缩小时间并不只能在空间上做文章，利用更多的信息有时候也可以缩小我们的时间复杂度**
